# Historia Terrarum 2 — Complete Rebuild Plan

> **For Hermes:** Do NOT execute yet. Await user confirmation after review.

**Goal:** Rebuild Historia Terrarum from scratch as a clean fork, keeping only the camera system from Stella Nostra, real-scale sphere, and Natural Earth data pipeline — with a deterministic 4096- equator / 2048-band spherical grid, binary land/water classification, and aggressive viewport culling at 10km resolution only.

**Architecture:** Deterministic grid (4096 equator segments, 2048 vertical bands, halving toward poles ending in 8 triangular polar cells). Every cell is either land or water (binary), **baked once at build time** by intersecting tile centers with Natural Earth 10m coastline → compact binary mask. The coastline shapefile and Python pipeline are build tools only — they never enter the game engine. At runtime, Godot loads the pre-baked binary mask and renders only visible cells via viewport culling. No LOD pyramid — single Level 0 mesh. No rivers, no borders, no tile ownership, no timeline.

**Tech Stack:** Godot 4.6.3, GDScript, Python (shapely + fiona + pyyaml), Natural Earth 10m shapefiles, existing Stella Nostra earth_camera.gd.

## Phase 2: New Deterministic Grid Math

### Task 2.1: Rewrite `compute_band_structure()` — deterministic mode

In `spherical_grid_generator.gd`, add a new static method that uses FIXED equator_segs=4096 and total_bands=2048:

```gdscript
## Compute deterministic band structure with fixed 4096 equator / 2048 bands.
## Halving: when cell_width < half_base_km, halve segment count.
## Halving repeats until 8 segments at the pole.
static func compute_deterministic_bands(
    radius_km: float,
    cell_km: float,
    equator_segs: int = 4096,
    total_bands: int = 2048
) -> Dictionary:
    var radius_m: float = radius_km * 1000.0
    var half_cell_m: float = cell_km * 0.5 * 1000.0  # 5 km threshold
    var min_segs: int = 8  # polar cap
    var eq_band: int = total_bands / 2  # 1024

    var band_segs: Array[int] = []
    band_segs.resize(total_bands + 1)
    band_segs[eq_band] = equator_segs

    # Northward
    var current_segs: int = equator_segs
    for b in range(eq_band + 1, total_bands + 1):
        var lat: float = -PI * 0.5 + PI * float(b) / float(total_bands)
        var ring_radius: float = radius_m * cos(lat)
        var cell_width: float = TAU * ring_radius / float(current_segs)
        while cell_width < half_cell_m and current_segs > min_segs and current_segs % 2 == 0:
            current_segs /= 2
            cell_width = TAU * ring_radius / float(current_segs)
        band_segs[b] = current_segs

    # Southward
    current_segs = equator_segs
    for b in range(eq_band - 1, -1, -1):
        var lat: float = -PI * 0.5 + PI * float(b) / float(total_bands)
        var ring_radius: float = radius_m * cos(lat)
        var cell_width: float = TAU * ring_radius / float(current_segs)
        while cell_width < half_cell_m and current_segs > min_segs and current_segs % 2 == 0:
            current_segs /= 2
            cell_width = TAU * ring_radius / float(current_segs)
        band_segs[b] = current_segs

    return {
        "total_bands": total_bands,
        "equator_segs": equator_segs,
        "band_segs": band_segs,
        "radius_km": radius_km,
        "cell_km": cell_km,
    }
```

**Verification:** Run test that confirms:

- `band_segs[2048]` (north pole) = 8
- `band_segs[0]` (south pole) = 8
- Halving only occurs once per threshold crossing (no double-halving at same band)
- Total tiles ≈ 4.0–4.3M

## Phase 3: Python Pipeline — Land/Water Classification (BUILD-TIME ONLY)

> **🛠️ This phase runs ONCE as a data generation step. The coastline shapefile, fiona, shapely, and Python are build tools — they never ship with the game. The game only loads the pre-baked `land_mask.bin` (~500 KB), a compact binary where each bit = one cell (land=1, water=0). This is a classic "bake once, load forever" data pipeline pattern.

### Data Flow

```
Natural Earth 10m coastline (.shp)
    ↓  [generate_land_mask.py — runs ONCE on the desktop]
land_mask.bin  (~500 KB, 1 bit per cell)
    ↓  [land_mask_loader.gd — loads at game startup]
is_land(band, segment) → bool  (~50ns lookup, zero allocations)
```

The pipeline can be re-run whenever the coastline data or grid resolution changes — but during normal development and gameplay, `land_mask.bin` is a static asset committed to the repo (or gitignored and generated once per clone).

### Task 3.1: Create `generate_land_mask.py`

New pipeline script that:
1. Computes the deterministic band structure (mirroring GDScript math)
2. For each tile, checks if its center point falls on land using Natural Earth 10m coastline
3. Outputs a compact `land_mask.bin` (binary file — 1 bit per cell = ~500 KB for 4M cells)

```python
#!/usr/bin/env python3
"""
generate_land_mask.py — Classify every tile as land or water.
Uses Natural Earth 10m coastline to test tile centers.
Outputs compact binary mask + JSON summary.
"""

import json, math, os, struct, sys
# pip install shapely fiona

EARTH_RADIUS_KM = 6371.0
EQUATOR_SEGS = 4096
TOTAL_BANDS = 2048
CELL_KM = 10.0  # approximate

SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
PROJECT_ROOT = os.path.dirname(os.path.dirname(SCRIPT_DIR))
SHAPEFILE_DIR = os.path.join(PROJECT_ROOT, "data", "shapefiles")
OUTPUT_DIR = os.path.join(PROJECT_ROOT, "data", "output", "grid_10km_ht2")
```

**Algorithm:**
1. Compute band structure deterministically
2. Load coastline shapefile via fiona → shapely MultiPolygon
3. For each tile (band, segment):
   - Compute lat/lon of tile center
   - Test if point is inside coastline polygon → land
   - Set bit in bit array
4. Pack bits into bytes, write binary file
5. Also write a JSON summary with band_segs + land_counts

**Performance (build-time, one-off):** 4M `polygon.contains(Point(lon, lat))` calls may take 2–5 minutes for the full coastline MultiPolygon. This is a one-time cost during data generation and does NOT affect game performance. Optimizations available:
- Pre-compute STR-tree spatial index on coastline parts
- Batch tiles by band, use bounding-box pre-filter

### Task 3.2: Create `land_mask_loader.gd` (GDScript)

### Task 4.2: Mesh generation — only visible cells

The 4M-cell full mesh is ~400 MB of vertex data — impossible to render at once. Instead:

**Approach: Viewport-frustum chunked mesh**
1. Divide Earth into ~100 geographic chunks (e.g., 10°×10° lat/lon blocks)
2. Each chunk is a separate `MeshInstance3D` with its own mesh
3. Each frame, check which chunks intersect the camera frustum
4. Only visible chunks have their meshes generated/visible
5. Chunks outside frustum or on the far side of Earth are hidden

**Chunk visibility test:**
- Compute chunk center + bounding sphere
- Test against camera frustum planes (6 planes)
- If chunk is on the far side (dot(camera_to_chunk, camera_to_earth_center) < 0), cull

**Initial approach (simpler):** Start with a single massive mesh at the tactical zoom level (camera at 7,500 km). Only cells within ~500 km of the camera's sub-point are rendered. This is ~2,500 cells — trivial.

### Task 4.3: Sub-point-based culling (MVP)

For the first implementation, use the simplest possible culling:

1. Compute camera's sub-point on the Earth surface (ray-sphere intersection from camera position to Earth center)
2. Render all cells within a configurable radius (e.g., 500 km) of that sub-point
3. As camera orbits, regenerate the visible cell mesh each frame (or throttle to every 3 frames)

This is wasteful in the long run but simple and correct for MVP.

## Risks & Open Questions

1. **Pipeline runtime (build-time only):** Intersecting ~4M tile centers against the Natural Earth 10m coastline polygon takes an estimated 2–5 minutes in Python. This is a one-time cost during data generation — NOT a runtime concern. Mitigations: STR-tree spatial index on coastline parts, bounding-box pre-filter per band, progress logging. Since this pipeline runs only on the desktop (not in the game), the cost is acceptable.

2. **Viewport culling at 10km detail:** A 500km radius at 10km resolution means ~2,500 cells visible at once. Each cell is 2 triangles (fan-triangulated) = 5,000 triangles. Trivial for modern GPUs. But as we zoom OUT, visible area grows quadratically — at Continental zoom (22,000 km), visible area is enormous. Fix: for HT2 v1, lock camera to Tactical zoom level (7,500 km) and disable higher rungs.

3. **Mesh regeneration per-frame cost:** Regenerating 2,500 cells every frame is wasteful. Throttle to every 3 frames. Even better: regenerate only on camera movement stop (after momentum decays).

4. **Polar cells:** The 8 triangular cells at each pole require special handling in `generate_tint()` — the existing code already handles pole cases with `bot_pole`/`top_pole` flags and single-vertex collapse. Verify with 8-cell poles specifically.

5. **Antarctica:** The coastline shapefile may not include Antarctica's ice shelf edge vs rock. Use the admin-0 shapefile for Antarctica's land boundary, not just coastline.

6. **Lake handling:** Natural Earth 10m coastline includes major lakes (Caspian Sea, Great Lakes). These will correctly register as "water" cells within continents.

7. **30% land percentage may be slightly off:** At 10km resolution, small islands (<10 km) may disappear if no tile center falls on them. This is acceptable — terrain can be refined later.
